# 星栈算力 · 上游供给与运营决策备忘

> 日期：2026-11-12。写给后续接手的 agent 和未来的自己。
> 执行细节见 [`自营上游接入行动清单.md`](./自营上游接入行动清单.md)，本文只记录"为什么这么定"。

## 一句话

早期以**个人身份 + 香港服务器**运营：模型能力由**平台自营上游**供给，不建独立中转服务；数据库继续用 **SQLite**；收款走**海外 MoR**；暂不开公司，但盯住转主体的触发条件。

---

## 1. 供给：不自建中转

- 仓库已有完整的中转层：`/v1/models`、`/v1/chat/completions`、SSE、多上游路由、三段计价、健康冷却、会话粘性、密钥加密。缺的只是上游供给。
- **平台自营 = 普通上游**，走同一张 `upstreams` 表、同一条路由、同一套结算。不为它写特殊分支。
- 起步组合：**DeepSeek + 硅基流动**；备选阿里云百炼、火山方舟。
- 通过 `STARSTACK_SEED_UPSTREAMS` 播种，幂等，任何失败都只打日志、不阻断启动。
- 定价口径：平台拿到售价全额（90% 记 owner 收益 + 10% 撮合费），所以**只需覆盖厂商成本**，不需要额外加 10%。自营按参考价定，不做最低价倾销，否则真实 provider 永远拿不到流量。
- 对外文案统一叫「官方供给 / 平台自营节点」，**不出现"中转站"**。

## 2. 数据库：保留 SQLite，不换 D1

- D1 只能走 Workers 绑定或 HTTPS API，每条语句一次网络往返；没有跨请求的交互式事务；本身也是单主写，**不解决扩展问题**。
- 真正的天花板是"单进程 + 内存态调度器"，换任何数据库都换不来 HA。
- 近期只做三件事：
  1. 备份 `starstack.db`、`gateway.key`、`agent.key`（缺 `gateway.key` 上游凭据全部解不开）；
  2. `synchronous=NORMAL` + 读写分离连接池；
  3. 账本聚合补 `(user_id, kind, source)` 索引。
- 迁移触发条件（出现两条再动手）：需要多实例 HA、持续写入 >100 tx/s、需要独立分析库、第二个服务共享数据、单库数 GB 且备份窗口不可接受。
- 真要迁，目标是 **Postgres**，不是 D1。

## 3. 厂商准入

- 分界线是**书面授权**，不是技术能不能接。
- 火山方舟：只允许内部使用或在自有产品内调用给最终用户，禁止单独向第三方提供。
- 智谱：明确禁止出租、分销、转售、二次封装、**服务中转、聚合中转**。
- MiniMax：禁止独立于应用的分许可/转售。
- DeepSeek：允许集成到下游，要求 key 保密、不得共享；商业转售需书面确认。
- 百炼、方舟、硅基流动的渠道/分销需要商务谈。
- 结论：**拿到授权前，只做"平台内测的模型调用能力"，不公开售卖任意模型 API。**

## 4. 主体：先个人

- 个人实名即可开通：DeepSeek、硅基流动、阿里云百炼、火山方舟、智谱、Moonshot、MiniMax。
- 转主体触发条件（任一）：要给客户开票、月流水数千以上、要公开推广、厂商要求企业认证才提额/签授权。
- 过渡顺序：个体户（几百元、可开票、可绑法人储蓄卡）→ 有限责任公司（10 万认缴、2 个股东、5 年内缴足）。
- 不建议一人有限公司（财产混同要连带责任）。

## 5. 收款

- 香港服务器 → 无 ICP 备案 → **支付宝/微信网站支付不可用**（需营业执照 + 备案，且主体一致）。
- 个人阶段唯一合规路径：**海外 MoR**。
  - 首选 **Creem**：3.9% + $0.40，可提现到支付宝，单笔 ≤5 万元，年约 30~60 万。
  - 备选 **Paddle**（5% + $0.50，审核严）、Dodo。
  - Stripe 大陆无账户；Lemon Squeezy 仅 PayPal 且产品路线不稳。
- 接入方式：先卖"额度包"，MoR webhook → 验签 → 幂等 → 调 `AddCredits` 记账；早期可手动开通兜底。
- 禁区：个人码做经营收款、发卡平台/二清、多开账号绕厂商限流。

## 6. 香港 + 海外域名的合规边界

| 事项 | 结论 |
|---|---|
| ICP 备案 | 不需要（服务器在境外） |
| 境内发票 | 开不了，对大陆企业客户是硬伤 |
| 个人信息 | PIPL 有域外效力；保持"只记 token 数、不记提示词内容"，补隐私政策和删除机制 |
| AI 内容标识 | 2025-09-01 起施行；写进 AUP 要求下游标注 |
| 生成式 AI 备案 | 个人 + 香港实际做不了；因此**保持邀请制，不公开面向大陆推广** |
| 个税 | 海外收入也要申报 |

## 7. 优先级

1. P0：DeepSeek + 硅基流动打通，非流式 + 流式 + 故障切换。
2. P0：每 key 日限额 + 平台日预算熔断。
3. P1：上游用量对账表、「官方」标识。
4. P1：四份法务页面 + Creem/Paddle 申请。
5. 以后：转个体户/公司。
